DeadlineIQ

A deadline tracker deployed live on AWS. I owned the reminders and notifications: smart, capped, and guaranteed never to message a student twice.

RoleNotifications & UX lead
Team4 people
My share7 of 23 use cases, ~4,700 lines
StackAWS serverless, React 19

The problem

Students juggle assignment deadlines across many modules. A tracker only helps if its reminders arrive at the right time, and don't turn into noise that gets ignored.

What I built

In a team of four, I owned the experience and notifications track, on a product deployed live on AWS.

  • A reminder engine on EventBridge and Lambda, with six rule types in priority order, quiet hours, and a hard cap of three notifications a day. Anything over the cap goes into a daily digest instead.
  • One place for delivery. All messages go through a single interface (SNS, with an SMTP fallback), so no feature has to know how messages are sent.
  • A live calendar feed. A token-protected subscription feed that I hand-wrote to the iCalendar standard (RFC 5545), so deadlines stay up to date in Google, Apple or Outlook calendars instead of being a one-off download.

The tricky part: never notify twice

Cloud functions get retried when something fails. Without care, a retry means a student gets the same reminder twice, which is exactly the kind of noise that makes people mute an app.

I made every send idempotent: before sending, the function makes a conditional write keyed on the date, the task and the rule. If that record already exists, the send is skipped, so a retried function can't message the same student twice.

I also wrote the reminder rules as a pure function that doesn't read the clock itself. That way every rule, quiet-hours case and cap scenario can be tested without waiting for real time to pass.

Result

DeadlineIQ placed 2nd in the Assignment Deadline Tracker category at the AWS × NYP Hackathon 2026.
